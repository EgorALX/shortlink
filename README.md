## О проекте

Консольный сервис сокращения ссылок на Java. Он превращает длинный адрес вроде https://www.baeldung.com/java-9-http-client в короткий вроде clck.ru/3DZHeG, считает переходы, блокирует ссылку после исчерпания лимита и сам удаляет ссылки, у которых истёк срок жизни. Пользователь не регистрируется: при первой созданной ссылке ему выдаётся UUID, и по нему программа понимает, какие ссылки его.

## Сборка и запуск

Нужны JDK 26 и Maven. Приложению достаточно стандартной библиотеки Java. Maven скачает JUnit и плагины сборки при первом запуске.
Команда mvn package собирает проект и прогоняет тесты, после неё программа запускается командой java -jar target/shortlink.jar. Можно и просто запустить класс com.shortlink.Main из IntelliJ IDEA.

## Настройки

Все параметры лежат в файле application.properties: домен коротких ссылок link.domain, длина кода link.code.length, срок жизни ссылки в минутах link.ttl.minutes, лимит переходов по умолчанию link.click.limit.default и максимальный лимит link.click.limit.max. По умолчанию ссылка живёт сутки, то есть 1440 минут.
Чтобы изменить настройки, скопируйте `src/main/resources/application.properties` в каталог, из которого запускаете программу. Оставьте в копии все пять параметров. Для срока жизни в один час задайте `link.ttl.minutes=60` и перезапустите программу. При ошибке в файле программа укажет проблемный параметр.

## Как пользоваться

Команды вводятся по одной в строке, а нужные данные программа спрашивает по шагам. Если на любом шаге ввести cancel, ввод отменится. Команда help показывает короткий список команд, а help с названием команды, например help edit, показывает подробности и пример.
Короткая ссылка создаётся командой create. Программа спрашивает длинный адрес, например https://www.baeldung.com/java-9-http-client, и лимит переходов, например 5, а если нажать Enter, лимит берётся из настроек. В ответ выводятся короткая ссылка, срок её действия и при первой ссылке ваш UUID.
Чтобы перейти по ссылке, достаточно просто вставить её в консоль, например clck.ru/3DZHeG. То же самое делает команда open clck.ru/3DZHeG, а команде open можно дать и только код 3DZHeG. После успешной передачи адреса системному браузеру программа засчитает переход и покажет остаток. При ошибке запуска браузера лимит сохранится, и команду можно повторить. Если лимит исчерпан или срок истёк, программа скажет, что ссылка недоступна.
Команда list показывает ваши ссылки: адрес, сколько переходов сделано из лимита, до какого времени ссылка действует и не исчерпан ли лимит. Командой edit limit можно поменять лимит переходов, а командой edit url адрес, на который ведёт ссылка. Новый лимит должен быть больше уже сделанных переходов, поэтому поднять лимит у заблокированной ссылки можно, а сделать его меньше уже потраченного нельзя. Удаляется ссылка командой delete. Менять и удалять ссылку может только её владелец.
Команда user показывает ваш UUID. Командой user с UUID, например user 3f1c9a52-6b1e-4f0a-9d7e-2c4b8a1f5e60, можно вернуться к работе под другим пользователем, а командой user new начать как новый пользователь. Ссылки, UUID и уведомления хранятся в памяти в течение одного запуска. Команда `exit` завершает сеанс. При новом запуске первый вызов `create` с успешным созданием ссылки выдаст новый UUID.

## Уведомления

Владелец ссылки получает уведомление, когда по его ссылке сделан последний разрешённый переход и когда ссылка удалена из-за истёкшего срока. Уведомления копятся для каждого пользователя отдельно и выводятся, как только он вводит любую команду. Тот, кто пытается перейти по недоступной ссылке, сразу видит, почему она недоступна.
После ввода каждой непустой команды программа сначала удаляет просроченные ссылки и проверяет уведомления. Пока консоль ждёт следующей команды, записи остаются в памяти. Перед открытием ссылки программа дополнительно сверяет срок действия, поэтому после истечения TTL переход заблокирован.

## Как устроен код

Код поделён на три части.
Пакет core это сама программа. В core.model лежат ссылка и результат перехода по ней, в core.service классы, которые всё делают: LinkService создаёт ссылки, считает переходы, проверяет срок жизни и права владельца, UserService выдаёт UUID, NotificationService хранит уведомления, CodeGenerator придумывает случайный код из букв и цифр. Каждый выданный код остаётся зарезервированным до конца сеанса, в том числе после удаления ссылки владельцем или по TTL. Настройки хранятся в AppConfig, тексты сообщений в Messages. Для открытия адреса сервис вызывает интерфейс Browser.
Пакет infra отвечает за связь с внешним миром. InMemoryLinkStorage хранит ссылки в памяти и реализует интерфейс LinkStorage из core.storage, ConfigLoader читает application.properties, а DesktopBrowser открывает адрес в браузере через интерфейс Browser. Благодаря интерфейсам хранилище и браузер можно заменить, не трогая логику.
Пакет cli отвечает за общение с пользователем: читает команды, спрашивает данные и печатает результат. В ConsoleInputHandler находится цикл чтения команд и справка help. LinkCommands выполняет команды со ссылками и пользователями. Класс Main читает настройки, создаёт все объекты и связывает их между собой.

## Тесты

Тесты лежат в папке src/test/java и запускаются командой mvn test или в IntelliJ IDEA через Run All Tests. Обычные тесты проверяют создание ссылок, проверку адресов и лимитов, подсчёт переходов, редактирование и удаление только владельцем, выдачу UUID, уведомления и чтение настроек. Сценарии из задания собраны в LinkScenarioTest: одна и та же ссылка у двух пользователей даёт разные короткие ссылки, ссылка блокируется после лимита, часовая ссылка удаляется при первой проверке после истечения срока, а со сроком сутки живёт целые сутки, и владелец получает уведомления. Чтобы не ждать час или сутки, в тестах используются часы, которые можно перевести вперёд.
Полная проверка перед сдачей запускается командой `mvn verify`. Она собирает JAR, запускает тесты и проверяет стиль основного кода и тестов через Checkstyle. Правила лежат в `checkstyle.xml`. GitHub Actions выполняет ту же команду при push и pull request. Отчёт о покрытии после тестов доступен в `target/site/jacoco/index.html`.
Отдельные тесты проверяют очистку при вводе следующей команды, сохранение последнего перехода при ошибке браузера и повторную генерацию при совпадении с ранее выданным кодом.
